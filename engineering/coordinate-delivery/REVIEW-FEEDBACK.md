# Actionable Review Feedback

Re-read the affected Review Proposals and enumerate attributable feedback by permanent provider ID. Return the open ticket to unassigned `ready-for-agent` through human authority, then return to the [Resume Gate](RECOVERY.md) with Review Feedback qualified as the sole source.

At the Resume Gate, invoke fresh shared Context Assembly for the checkpoint's Ticket Origin Repository, fixed `Delivery Context` profile, and permanent activation-ticket root. When the returned file is not `Complete`, enter the human boundary. Its new path becomes the recovered attempt's Authority input.

Reuse each affected delivery's existing Review Proposal. Launch fresh affected Implementation Agents from the checkpoint with the new Context Pack path. For each changed head, refresh repository validation and pass that same path to `code-review` in **Standards only** mode. Rerun every invalidated obligation with fresh Validation Agents, then pass the path to `code-review` in **Spec only** mode over the complete affected target set. Downstream agents reuse the file and perform no authority-provider read. Repeat the correction and fresh-review sequence until clean or a genuine human boundary applies. Preserve proposals and only the evidence that remains current under [Recovery's complete dependency rule](RECOVERY.md).

**Complete when:** every implementation and review input preserves the refreshed Authority input, every actionable item has an attributable disposition, each affected proposal points to its refreshed exact head, all dependent evidence is current, and no duplicate proposal exists.
