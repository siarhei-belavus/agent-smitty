# Actionable Review Feedback

Re-read the affected Review Proposals and enumerate attributable feedback by permanent provider ID. Return the open ticket to unassigned `ready-for-agent` through human authority, then return to the [Resume Gate](RECOVERY.md) with Review Feedback qualified as the sole source.

At the Resume Gate, retain Delivery Context as the selected profile and the checkpoint's exact permanent activation-ticket root. Reassemble that fixed selection from provider truth without discovering another root or switching profiles. Only `Complete` continues. The refreshed lossless Context Pack becomes the Authority input for the recovered attempt; `Incomplete` or `Ambiguous` enters the human boundary.

Reuse each affected delivery's existing Review Proposal. Launch fresh affected Implementation Agents from the checkpoint with the exact Delivery Context profile, permanent root, `Complete` result, and refreshed lossless Context Pack. For each changed head, refresh repository validation and pass that same Authority input to `code-review` in **Standards only** mode. Rerun every invalidated obligation with fresh Validation Agents, then pass it to `code-review` in **Spec only** mode over the complete affected target set. Repeat the correction and fresh-review sequence until clean or a genuine human boundary applies. Preserve proposals and only the evidence that remains current under [Recovery's complete dependency rule](RECOVERY.md).

**Complete when:** every implementation and review input retains the fixed Delivery Context profile and permanent root with an explicit `Complete` result and lossless Context Pack; every actionable item has an attributable disposition; each affected proposal points to its refreshed exact head; all dependent evidence is current; and no duplicate proposal exists.
